# 随手笔记 NoteLab

一个自己用的极简笔记网页：**打开就能写，用 `#标签` 归类，能搜、能翻。**
不登录、不上云、不联网 —— 数据只存在自己这台电脑的浏览器里。

> Day 7 完成 MVP。技术路线见 `TECH_DESIGN.md`，功能与验收标准见 `PRD.md`。

## 二、怎么用（对照 PRD 的五个功能）

页面分成**三个视图**（Day 13 新增），顶部导航栏切换：

| 视图 | 干什么 |
|---|---|
| **写笔记** `#/write` | 输入框 + 最近的 3 条笔记（刚保存的会立刻出现在这里） |
| **所有笔记** `#/notes` | 搜索框 + 标签筛选 + 完整笔记列表 |
| **翻一翻** `#/review` | 随机翻出一条旧笔记来回顾 |

| 功能 | 怎么用 |
|---|---|
| **F1 写笔记** | 打开页面默认在「写笔记」，光标就在输入框里，直接打字；按 `Ctrl + Enter` 或点「保存」 |
| **F2 标签归类** | 正文里写 `#标签`（例如 `#想法`），保存后自动归类；去「所有笔记」点左侧标签可筛选，再点一次取消。标签区分大小写，一条最多 5 个 |
| **F3 关键词搜索** | 去「所有笔记」，在搜索框输入即筛选，正文和标签都能搜到，命中的词会高亮 |
| **F4 随机回顾** | 去「翻一翻」点按钮，随机翻出一条旧笔记（笔记少于 3 条时会提示先多记几条） |
| **F5 本地保存** | 自动保存，关掉浏览器再打开笔记还在；不需要登录 |

> 切换视图时地址栏会跟着变（`#/write`、`#/notes`、`#/review`），
> 所以浏览器**后退/前进按钮能用**，可以把「上一个视图」当一次返回。细节见 `TECH_DESIGN.md` 第 7.1 节。

## 三、演示模式与四种页面状态（Day 8 新增 / Day 13 跟随列表搬到「所有笔记」视图）

四种状态挂在**笔记列表**上，所以看这四种状态要去「所有笔记」视图：

| 状态 | 什么时候出现 | 页面表现 |
|---|---|---|
| **加载中** | 数据还没取回来 | 三条灰色骨架卡片 + 「正在取数据…」 |
| **有数据** | 正常情况 | 笔记卡片列表（标签 + 时间） |
| **空** | 取数成功但一条都没有 | 一句明确的话，告诉用户下一步做什么 |
| **出错** | 取数失败 | 说明失败原因 + 一个「重试」按钮 |

本地预览这四种状态，**两种方式**：

**方式一（推荐，不用打网址）**：进「全部笔记」视图，列表下方有一行
「想看这一页在『加载中 / 空 / 出错』时分别长什么样？打开演示模式 →」，点它就行。
进去之后顶部提示条上能直接切换四种状态。

**方式二（直接甩网址）**：

```
http://localhost:8123/?demo=1&state=loading#/notes    加载中
http://localhost:8123/?demo=1&state=success#/notes    有数据
http://localhost:8123/?demo=1&state=empty#/notes      空
http://localhost:8123/?demo=1&state=error#/notes      出错
```

> 参数和 `#` 的顺序不能反：查询参数在前、`#` 在后。
> 如果只写 `?demo=1&state=error` 不加 `#/notes`，会先落在「写笔记」视图，
> 点一下顶部「全部笔记」就能看到出错状态。

> **Day 13 修的一个真问题**：四种状态一直是好的（代码没坏），但**只能靠手打网址参数才能看到**，
> 页面上没有任何入口 —— 你正常打开页面（尤其双击 `index.html`）永远只有一种状态，
> 这四种状态对你等于不存在。现在补了上面那个常驻入口。
> 教训：**功能在 ≠ 用户走得到。** 这类"入口/可达性"问题，DOM 桩测试查不出来
> （它报 34/34 全过），必须用真实浏览器渲染检查，见下一节。

- `?demo=1` 表示**演示模式**：数据来自 `mock-data.js` 的 10 条假笔记，不会写入你的真实笔记
- 不加 `?demo=1` 就是正常模式，用你自己记录的真实数据
- 演示模式下保存会被拦下并提示，避免假数据混进真数据

> **为什么现在用假数据**：先把"数据怎么显示"这件事做对，再解决"数据从哪来"。
> 第 3 周接真实接口时，**只改 `mock-data.js` 这一个文件**，页面和组件都不用动。

### 小坑记录：链接别写 `./`

提示条里的「退出演示」当初写成了 `<a href="./">`，结果**用文件方式打开（双击 `index.html`）时点它会跳到文件夹列表**，而不是回到页面。

原因：`./` 的意思是"当前目录"。用服务器打开时，当前目录的默认文档是 `index.html`，看着没事；但用 `file://` 打开时，当前目录就是那个文件夹本身，浏览器只能把文件夹内容列出来。

**规则：要跳回页面就明确写 `index.html`，不要用 `./`。** 两种打开方式下都正确。

完整手册见 `ROLLBACK.md`，里面有「什么情况必须回滚」的判断表。

> ⚠️ 总闸的三种结果：**✓ 通过 / ✗ 不通过 / ⊘ 没验到**。
> **⊘ 不算通过** —— 没给 `--url` 时公网那三项就是 ⊘，别把一片绿灯当成全都验过了。
>
> 红项还分两级：**阻断级**（线上不可用 / 丢数据 / 泄密 / 回滚基线说不清）不许发布；
> **非阻断级**（能用，只是体验差或文案缺一步指引）允许带病发布，但**必须**已登记欠账。
> 分级的理由：一刀切的"有红项就不许发布"看着严，其实会被绕过 ——
> 只要有一项长期红着又没人修，人就会养成忽略那行红字的习惯，
> 等真出阻断级问题时它也没人看了。闸被绕过去，比没有闸更糟。

### 数据流（一句话）

输入框 → `app.js` 拆标签组装笔记对象 → 存进 localStorage 的唯一位置（`loadNotes()` / `saveNotes()` 两个函数）
→ 打开页面时读回内存 → 渲染成列表 / 搜索 / 随机回顾。**全程不经过任何服务器。**

> Day 17 起服务端那一半已经准备好（`cloudbase-functions/notes/` + `db/`），
> Day 18 又把**写接口**（POST）补上 —— 读和写现在是**同一个云函数**，因为你一个路径
> `/api/notes` 只能绑一个函数，GET 和 POST 只能住在一起。
> Day 19 给这个函数**分了层**：查数据库的代码全部收进 `repository.js`，
> 上层只管"要什么、合不合法、失败算什么错"（分层图见 `TECH_DESIGN.md` 第 7.2 节）。
> Day 22 补上了 **PATCH（改）与 DELETE（删）**，四类操作闭环。删除是**软删除**：
> 只把 `is_deleted` 打成 1，行留在库里，一句 SQL 就能找回来（见 `db/README.md`）。
> 但**前端还没切过去** —— 页面仍然只读 localStorage。
> 切换的前提是先有一个真的 CloudBase 环境（见 `DEPLOY.md`）。
> 切换时前端只该改取数那一处，因为接口返回的形状就是照着 `mock-data.js` 定的。

## 六、怎么改（约束，来自 TECH_DESIGN 第 7 节）

1. 不加任何第三方依赖、不用 npm、不用构建工具
2. 不发任何网络请求，断网必须完全可用
3. 不引 CDN 上的字体和图标
4. 存储读写只能写在 `loadNotes()` / `saveNotes()` 里，别处不许直接碰 localStorage
5. 单个文件超过 500 行就拆开
6. **改样式必须过对比度门槛**（Day 9 起）：普通文字 ≥ 4.5:1，按钮和输入框的边框 ≥ 3:1。
   规则、算法和自检小脚本见 `DESIGN_REVIEW.md`——加新颜色前先算，别靠眼睛估
7. **改了筛选相关代码先跑回归**（Day 12 起）：`node skills/notelab-filter-check/run.js`
   三种情况全 PASS 再提交，调用记录自动留在 `skills/notelab-filter-check/RUNLOG.md`
8. **视图切换只用 `#` 哈希**（Day 13 起）：不要引入 History API 或路由库，
   也不要给 `.view` 写 `display`（会盖掉 `[hidden]`，Day 10 已经踩过这个坑）
9. **状态断言要过滤元素**（Day 13 起）：数"有几张卡片"时先按 class 过滤，
   别直接数 `children.length`（面板里除了卡片还有一行提示，会数错）。
   **元素被 `hidden` 藏起来不等于不在 DOM 里** —— 数卡片还要限定到 `#note-list` 里面，
   否则会把「写笔记」视图里那 3 张「最近 3 条」一起算进来
10. **改了"页面上的入口 / 可达性"先跑真实渲染检查**（Day 13 起）：
   `node skills/notelab-filter-check/render-check.js`
   行为层（`run.js`）只能证明"代码是对的"，**证明不了"用户看得见"** ——
   Day 13 那个"四种状态没有入口"的问题就是被这一层漏掉、被你人肉发现的
11. **量窄屏别用浏览器的 `--window-size`**（Day 14 起）：无头浏览器的窗口宽度有
   约 504px 的下限，传 390 拿到的布局视口其实是 504、截图却按 390 裁 ——
   看着像"页面溢出、按钮被挤出屏幕"，是**测量工具的假象**。
   用 `http://localhost:8123/skills/notelab-filter-check/mobile-probe.html` 量
12. **拿真人当尺子**（Day 14 起）：新功能上线前，`TEST_PLAN.md` 照着找一个人用一遍。
   测试期间**不许改代码**（中途改了，后面几步测的就不是同一个版本）
13. **连库的代码只照文档写，不靠记忆猜**（Day 17 起）：
   CloudBase 的 MySQL 连接、VPC、环境变量都写在官方文档里，
   和"一般 Node 项目连 MySQL"的默认做法**不一样**（尤其"必须配 VPC、配了之后不能上公网"
   这一条）。写之前先把文档读到手；读不到就不写，宁可空着
14. **占位符个数必须等于参数个数**（Day 17 起）：拼 SQL 时值一律走 `?`。
   写错的后果是运行时才报数据库的错，报的不是"你少传了一个参数"。
   改了 `buildWhere()` 之后先跑 `node skills/notelab-api-check/check.cjs`，
   A 层会把六种参数组合逐个核这条
15. **一件事只有一个名字**（Day 17 起）：不接受"URL 里叫 none、内部叫 __none__"这种
   隐式换算 —— 两个函数之间靠看不见的约定耦合，谁忘了换算就**静默筛不到、还不报错**。
   这是自检脚本 B-11 当天抓出来的，最后把那层换算整个删掉了
16. **先校验、再连库**（Day 18 起）：`POST` 里"字段不合法"这类判断必须排在
   **申请数据库连接之前**。两个好处：① 坏请求根本不占连接、不吵数据库；
   ② 这些分支能在**没有数据库的本机**被测到（C/D 两层就是这么来的）。
   自检里专门有一条守卫 `validation precedes connection`，防止以后被人把顺序调换
17. **防重复提交靠唯一索引兜底，不许"先查再插"**（Day 18 起）：
   「查一下有没有 → 没有就插」中间有时间差，两次请求同时进来会**双双通过检查**、
   插出两行。正确做法是给 `notes.client_token` 建 `UNIQUE` 索引，
   插的时候撞键（`ER_DUP_ENTRY` / 1062）→ 回 `409`。
   拦住重复的**不是那段 if**，是数据库那条约束。详见 `db/README.md` 第二、三节
18. **SQL 只许待在数据访问层**（Day 19 起）：全项目只有
   `cloudbase-functions/notes/repository.js` 里出现 SQL 语句、`conn.query` 和事务调用。
   上层（`read.js` / `write.js`）只调用仓库，自己一句 SQL 都不写 ——
   这样"表里有什么列"就只被一个文件知道，换数据库 / 改表结构只动那一处。
   这条约定**看不见**（写错了不会报错，只是分层慢慢烂掉），所以由自检
   **F 层**直接读源码守着。改了分层先跑 `node skills/notelab-api-check/check.cjs`
19. **出错提示要告诉用户"去哪看"**（Day 20 起）：面向用户的错误文案不许只写"出错了"。
   同一句"取不到数据"至少是三种病（跨域没过 / 地址不对 / 返回形状不对），
   治法完全不同 —— 认错方向就白查半天。所以提示里要写清**看哪里、什么现象对应什么病**
   （本项目 `api.js` 的 `corsHint()` 就是照这个写的，接线自检 D 段专盯它）
20. **接真接口的开关默认关着**（Day 20 起）：`api.js` 里没配地址时 `isEnabled()` 返回 false，
   页面照旧读 localStorage。这样"接线"这件事不会因为代码合进来就改动线上行为 ——
   接线自检 A-01 守的就是这条底线
21. **删除必须"指名道姓"，绝不静默成功**（Day 22 起）：DELETE 要求显式给 `id`，
   缺了回 400、查不到回 **404**，**不做批量删除**。
   理由：删除是四类操作里唯一"错了就找不回来"的那个 —— 新增错了是多一条，删掉就好；
   删除错了是少一条，而少掉的内容没有任何地方能再变出来。
   "看起来成功但什么都没删"是最坏的结果：用户以为删了，其实没删，也不知道要去确认
22. **软删除的"跳过"只有一处实现**（Day 22 起）：`repository.withNotDeleted()`。
   别处不许自己拼 `is_deleted = 0` —— 拼漏了**不会报错**，只会让已删的笔记静默地又冒出来。
   配套两条：DELETE 只改标记不删行；`note_tags` 标签行也留着（恢复时笔记才是完整的）。
   找回的方法是 `db/verify.sql` 第 ⑨ 段那句人工 `UPDATE`，**故意没做成自动清理**
23. **面向用户的报错文案只有一个出处**（Day 23 起）：`errors.js`。
   三类错误（**A 存储类** 存不下/读不出、**B 网络类** 取不到数据、**C 服务端类** 接口回了失败）
   的提示语全在那一张表里，`app.js` / `api.js` 只取不来写。
   每条文案要过三关：**中文** / **说清发生了什么** / **带一句下一步看哪或做什么**。
   一句"未知错误"也是提示，但它把排查成本整个推给用户 —— 那不叫提示，叫承认失败。
   原始错误（`QuotaExceededError` 之类）**只进 `console`**，绝不进界面
24. **前端脚本之间不许有同名的顶层 `const` / `let`**（Day 23 起）：
   经典脚本（不带 `type="module"`）的顶层 `const` / `let` 会进**同一个全局词法作用域**，
   两个文件都写 `const ERRORS = …` 的结果是 `SyntaxError`，后加载的那个脚本**整个不执行**。
   ⚠️ 这个错在 DOM 桩测试（`vm` 沙箱）里**撞不出来**（vm 里每个脚本作用域是分开的），
   表现是"行为层 41/41 全绿、真实浏览器白屏" —— 由自检 `L-4` 扫这个重名，
   **改了前端顶层变量名的，必须同时跑一次可见层 `render-check.js`**
25. **密钥只以"环境变量名"的形式出现**（Day 23 起，上线红线）：
   仓库里可以有 `process.env.DB_PASSWORD`（那是**读名字**），
   不可以有 `password = "真实的值"`。密码放 `.env`（已被忽略）或云函数控制台的环境变量里。
   每次提交前跑 `node skills/notelab-safety-check/scan.cjs`，必须是 **0 条命中**。
   ⚠️ 推上公开仓库是**不可撤回**的 —— 删文件救不了已经泄的密钥，只能去服务商后台吊销
26. **笔记数据要验两层**（Day 24 起）：
   第一层"这是不是一个数组"（`loadNotes` 早就有），
   第二层"数组里**每一条**是不是合格的笔记"（`sanitizeNotes` / `isUsableNote`）。
   ⚠️ 只验第一层会漏掉**半好半坏**的数据：数组里混进 `null` 或缺 `content` 的条目时，
   它照样是个合法数组，会一路走到渲染函数里炸掉
   （`TypeError: Cannot read properties of null (reading 'tags')`）。
   ★ 反直觉的是：数据**整块**坏掉反而没事 ——
     `JSON.parse` 抛错有 `catch` 接、顶层不是数组有 `Array.isArray` 拦，都会说人话；
     缺口恰恰在"半坏"这一档。
   ★ 三个入口（本地存储 / 演示模式 / 真接口）**都要过**这一层，只堵一个等于没堵。
   回归断言在 `skills/notelab-filter-check/run.js` 的 E 段（E-1～E-8），
   复现工具是 `skills/notelab-bug-hunt/hunt.cjs`（16 个刁钻用例，必须是 0 报错）
27. **上线前必跑发布前检查**（Day 25 起，Day 26 改为分级）：
   `node skills/notelab-release-check/check.cjs`。
   ⚠️ 它的结果有三种：**✓ 通过 / ✗ 不通过 / ⊘ 没验到**，**⊘ 不算通过** ——
   没给 `--url` 时公网那三项就是 ⊘。把"没验到"和"验过了没问题"混为一谈，
   是发布前检查最容易犯也最致命的错：绿灯一片，其实好几项根本没查。
   ★ 补上 ⊘ 的办法：上线时给 `--url`，它会真的 GET 一次 `/api/notes`。
   ★★ 红项**分两级**（Day 26 补）：
     - **阻断级** → 不许发布。判据是"它红的时候线上会怎样"：
       线上不可用 / 数据会丢 / 密钥外泄 / **回滚基线说不清**。
     - **非阻断级** → 允许带病发布，但**必须**已登记成欠账（如 D-3 云函数 500 文案）。
