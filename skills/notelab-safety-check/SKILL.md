# notelab-safety-check｜上线红线自检（Day 23 建立）

两个脚本，各管一件事，合起来是"能不能放心推上去"：

| 脚本 | 管什么 | 什么时候跑 |
|---|---|---|
| `scan.cjs` | **密钥排查**：仓库里有没有密钥的值、`.env` 有没有被忽略 | 每次提交前；改动 `.gitignore` / 配置相关代码后必须跑 |
| `messages.cjs` | **错误提示**：三类错误是不是都有中文人话、界面上还有没有裸报错 | 改动任何提示文案 / 新增错误处理分支后 |

```bash
node skills/notelab-safety-check/scan.cjs                # 密钥排查
node skills/notelab-safety-check/scan.cjs --selftest     # 证明扫描器自己有效
node skills/notelab-safety-check/messages.cjs            # 错误提示
node skills/notelab-safety-check/messages.cjs --selftest # 证明文案扫描不是空转
```

要求：Node 22+，零依赖。

---

## 为什么"密钥排查"排在最前面

功能做错了明天能改；**代码推到公开仓库是不可撤回的** ——
密钥一旦上去，就算下一秒删掉，fork、缓存、镜像站都还留着。
所以它是红线，不是待办。

## scan.cjs 的四段

1. **扫描范围**：列出会扫哪些文件，并分成"会推上仓库的"和"已被忽略的"。
   这个区分比"扫到几处"更要紧 —— 被忽略的文件根本推不上去，
   里面就算有密码也不是泄露。混在一起报，`.env` 里那个正常存在的密码会天天报警，
   报久了就会有人把这条检查关掉。
2. **8 条规则**：`sk-` / `AKIA` / `ghp_` / `xox?-` / 私钥块 / 连接串带密码 /
   硬编码赋值 / 长串指纹。
3. **名字与值分开**：`process.env.DB_PASSWORD` 是**读名字**，恰恰是"没有硬编码"的证据，
   不能和真值混在一起报。
4. **`.env` 本身**：在不在版本库、在不在 git 历史、有没有被忽略。

### 三条调规则时踩过的坑（改规则前先看这个）

| 坑 | 怎么处理的 |
|---|---|
| **扫源码不剥 URL** → 文档地址 `…/database/configuration/db/tdsql/initialization` 被"长串"规则当成 base64 | 先 `stripUrls()` 再扫 |
| **只查单个关键字** → git 提交号（40 位小写十六进制）被当成密钥 | R8 要求"大小写数字都有"，提交号天然不含大写 |
| **测试夹具被自己扫出来** → 第一版把假密钥样本写进源码，R1~R8 全红 | 样本改用短片段**运行时拼接**，源码里不留完整字面量 |

### ★ 为什么必须有 `--selftest`

"扫描结果 0 条"有两种可能：**真的干净**，或者**规则根本没生效**。
这两种看起来一模一样。`--selftest` 的做法是喂一段**假的**密钥进去，
看 8 条规则是不是每条都叫得应。有一条叫不应的，那条规则就是摆设。

## messages.cjs 的三类错误

| 类 | 什么时候出现 | 例子 |
|---|---|---|
| **A 存储类** | 存不下 / 读不出本地数据 | 隐私模式、空间写满、数据坏了 |
| **B 网络类** | 取不到接口的数据 | 跨域、地址不对、返回形状不对 |
| **C 服务端类** | 接口明确回了失败 | 400 / 404 / 409 / 500 |

每条文案要过三关：**是中文** / **说清发生了什么** / **带一句下一步看哪或做什么**。
一句"未知错误"也是提示，但它把排查成本整个推给了用户 —— 那不叫提示，叫承认失败。

### 今天改掉的那句裸报错

**改前**：`saveNotes()` 失败一律显示"浏览器不允许本地存储"。
存储**空间写满**时这句话是**错的** —— 用户会以为浏览器坏了，
而真正的解法（删几条旧笔记）他根本想不到，于是数据一直丢。

**改后**：`errors.js` 里的 `describeStorageError()` 把
`QuotaExceededError: The quota has been exceeded.` 分成三类
（`quota` / `unavailable` / `corrupt`），各给一句能照着做的话。
原始错误只进 `console`，不进界面。

### ★★ 一个必须记住的坑：桩测试全绿、真实浏览器白屏

Day 23 第一版在 `api.js` 和 `app.js` 里都写了 `const ERRORS = …`。
**经典脚本（非 module）的顶层 `const` / `let` 共享同一个全局词法作用域**，
重名会直接 `SyntaxError: Identifier 'ERRORS' has already been declared`，
后加载的 `app.js` **整个不执行**。

当时的表现是：

- DOM 桩测试 `run.js`：**41/41 全绿**（`vm` 沙箱里每个脚本作用域是分开的，撞不出这个错）
- 真实浏览器 `render-check.js`：**11/23，页面白屏**

→ 这是 Day 13 那条教训的新版本：**桩测过了不等于用户看得见。**
现在由 `L-4` 扫这个重名，行为层的改名要同时跑一次可见层。

## 明确**没**验到的

1. **git 历史里曾经提交过的值**：本脚本只查"`.env` 这类文件进没进过历史"。
   如果某次把密码直接写进了 `db.js` 又提交过，要另外用
   `git log -S'<那个值>' --all` 查。
2. **服务端/控制台里的环境变量**：云函数控制台上配的 `DB_PASSWORD` 不在这个脚本的视野里，
   它只管仓库。
3. **`.env.example` 被人填了真值还提交上去**：`S-07` 会扫它，但前提是那个人没顺手改名成 `.env.local`。
4. **界面上文案的"好不好懂"**：脚本只能验"是中文、有下一步"，
   读起来顺不顺还得人来（见 `TEST_PLAN.md`）。
