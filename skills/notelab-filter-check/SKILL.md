# Skill：NoteLab 筛选交互自检

## 这个 Skill 检查什么（一句话）

> 搜索框输入关键词后，页面是不是**该出结果出结果、该说没找到就说没找到、清空后能回到全部**。

## 什么时候用

- 改了 `app.js` 的 `getVisibleNotes()` / `renderNotes()` / 搜索框事件绑定
- 改了 `index.html` 里搜索框、笔记列表、空状态的结构
- 改了 `styles.css` 里 `.empty-state` 的显隐（防止再犯 Day 10 那类 `hidden` 被 `display` 盖掉的错）
- 提交前的例行回归

## 什么时候不用

- 只改了错别字、注释
- 改的是「翻一翻」或保存逻辑（与筛选无关，别滥用）

## 步骤

### 1. 自动测试（约 2 秒，零依赖）

在项目根目录执行：

```
node skills/notelab-filter-check/run.js
```

- 三种情况共 10 项断言 + 标签点击附加用例 4 项
- 全部 PASS 时退出码 0；任何 FAIL 退出码 1，修完重跑
- 每次运行自动往 `RUNLOG.md` 追加一行调用记录（何时、谁、结果）——那就是"真实调用过"的证据

### 2. 人工确认（改了样式或交互时才做）

浏览器打开 `http://localhost:8123/?demo=1&state=success`，然后：

1. 搜索框输入「想法」→ 列表只剩带 `#想法` 的，状态栏显示命中数
2. 输入「不存在词」→ 出现明确的"没有找到"提示，不是一片空白
3. 清空搜索框 → 恢复全部 10 条
4. 点左侧一个标签 → 只剩该标签的；再点一次 → 取消恢复

### 3. 留痕

- `RUNLOG.md` 由脚本自动维护，**不要手改**
- 把结论（PASS/FAIL + 一句话）写进当天的回复或提交说明

## 原理（为什么没有浏览器也能测）

`run.js` 用约 70 行的 DOM 桩"骗过" `app.js`（假的 `document` / `localStorage` / `location`），
让它在 Node 里完整跑起来；然后**通过 app.js 真实绑定的事件监听器**驱动搜索框，
断言的是真实渲染结果（列表子元素数、状态栏文案、空状态显隐）——
不是对着代码"人肉模拟一遍"。

这也是它和「在浏览器里点一遍」的区别：能进 Git、能重复、能留痕。

## 边界（这个 Skill 不检查什么）

- 不检查视觉效果（颜色、间距——那是 DESIGN_REVIEW.md 的 R1–R6 管的）
- 不检查保存 / 删除 / 翻一翻
- 不覆盖移动端（PRD 第 5 节本来就不做）
