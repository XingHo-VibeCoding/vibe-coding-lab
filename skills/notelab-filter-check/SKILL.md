# Skill：NoteLab 交互与页面状态自检

## 这个 Skill 检查什么（一句话）

> 搜索后**该出结果出结果、该说没找到就说没找到、清空能回全部**；
> 三个视图**该显示哪个就只显示哪个**；
> 列表的四种状态（加载中 / 有数据 / 空 / 出错）**在真实浏览器里真的看得见**。

## 什么时候用

- 改了 `app.js` 的 `getVisibleNotes()` / `renderNotes()` / `setView()` / `renderStatePanel()` / 搜索框事件绑定
- 改了 `index.html` 里搜索框、笔记列表、空状态、视图 `<section>`、演示模式入口的结构
- 改了 `styles.css` 里 `.empty-state` / `.view` / `.state-panel` / `.demo-entry` 的显隐
  （防止再犯 Day 10 那类"`display` 把 `hidden` 盖掉"的错）
- **改了四种状态的进入方式**（Day 13 的真实事故：状态本身是好的，但页面上没有入口，用户走不到）
- 提交前的例行回归

## 什么时候不用

- 只改了错别字、注释
- 改的是「翻一翻」或保存逻辑且不涉及列表渲染
- 没装浏览器时：第二层会自动 SKIP，第一层照样能跑

## 步骤

### 1. 行为层：DOM 桩（约 2 秒，零依赖）

在项目根目录执行：

```
node skills/notelab-filter-check/run.js
```

- 三组共 **34 项断言**：A 视图切换（7）/ B 筛选（13）/ C 四种页面状态（14）
- 全部 PASS 时退出码 0；任何 FAIL 退出码 1，修完重跑
- 每次运行自动往 `RUNLOG.md` 追加一行调用记录——那就是"真实调用过"的证据

### 2. 可见层：真实浏览器渲染（约 15 秒）

```
node skills/notelab-filter-check/render-check.js
```

- 用本机 Edge / Chrome 的无头模式把页面**真正渲染一遍**，抓回最终 DOM，
  断言关键元素的 `hidden` 状态与内容，共 **23 项断言**
- 覆盖：正常模式下那个"进演示模式的入口"在页面上真的可见（R-3）、
  四种状态各自的真实长相、以及**双击打开（`file://`）也要能用**（R-19 ~ R-23）
- 服务已在跑时加 `--no-serve`，不要重复起
- 没装浏览器会打印 SKIP 并退出 0（不算失败，但等于这一层没被验证，心里要有数）

### 3. 人工确认（改了交互手感时才做）

浏览器打开 `http://localhost:8123/?demo=1&state=success#/notes`，然后：

1. 搜索框输入「想法」→ 列表只剩带 `#想法` 的，状态栏显示命中数
2. 输入「不存在词」→ 出现明确的"没有找到"提示，不是一片空白
3. 清空搜索框 → 恢复全部 10 条
4. 点左侧一个标签 → 只剩该标签的；再点一次 → 取消恢复
5. 点顶部三个导航 → 地址栏跟着变成 `#/write` `#/notes` `#/review`，浏览器后退键能退回上一个视图

### 4. 留痕

- `RUNLOG.md` 由两个脚本自动维护，**不要手改**
- 把结论（PASS/FAIL + 一句话）写进当天的回复或提交说明

## 原理：为什么需要两层

**第一层（`run.js`）查行为。** 用约 70 行的 DOM 桩"骗过" `app.js`（假的 `document` /
`localStorage` / `location`），让它在 Node 里完整跑起来；然后**通过 app.js 真实绑定的事件监听器**
驱动搜索框与导航链接，断言的是真实渲染结果，不是对着代码"人肉模拟一遍"。
好处：能进 Git、能重复、能留痕、秒级反馈。

**第二层（`render-check.js`）查可见。** 第一层有个根本盲区：它只认"JS 把哪个属性设成了什么"，
**回答不了"用户在浏览器里到底看得见什么"**。Day 13 的真实事故就卡在这个盲区：
`run.js` 报 34/34 全过，但用户在「全部笔记」里根本看不到四种状态——
因为状态只能靠手打 `?demo=1&state=…` 进入，页面上没入口。
**桩测试给了一个假的安全感。** 所以第二层必须用真实浏览器。

两层的关系：**第一层快、查逻辑；第二层慢、查"用户能不能看见"。都不能省。**

## 两个反复踩的坑（写在这里，别再踩第三次）

1. **数元素个数一定要先限定范围。**
   `panel.children.length` 会把"正在取数据…"那行提示也算进去；
   全局数 `class="note-item"` 会把**被 `hidden` 藏起来的「写笔记」视图里那 3 张「最近 3 条」**
   一起算进来（13 而不是 10）。
   **元素藏起来了不等于不在 DOM 里。** 数之前先限定到具体容器（`countList()`）。
2. **"元素存在"不等于"用户看得见"。**
   要断言的是可见性（`hidden` 状态 + 祖先链条），不是元素在不在。

## 边界（这个 Skill 不检查什么）

- 不做像素级视觉判断（颜色、间距——那是 `DESIGN_REVIEW.md` 的 R1–R6 管的）
- 不检查保存 / 删除 / 翻一翻
- 不覆盖移动端（PRD 第 5 节本来就不做）
